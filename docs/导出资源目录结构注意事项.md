# 导出资源目录结构注意事项

## 问题记录

本次最初只实现了优先使用 `OriginalPath` 的容器路径导出。这个实现对 `ResourceManager.Container` 和 `AssetBundle.Container` 中有明确路径的资源有效，但对普通 `resources.assets`、`sharedassets*.assets` 这类没有 `OriginalPath` 的资产会继续回退到 `Assets/类型名`。

这会导致用户看到导出结构仍然像旧逻辑，例如顶层出现 `AnimationClip`、`Texture2D`、`Shader` 等目录。

第二次验证时又发现一个容易误判的点：Prefab 是由 `PrefabExportCollection` 导出的，主导出资产可能是处理阶段生成的 `PrefabInstance`。这个生成资产本身没有来源文件路径，即使普通资源已经进入 `Everything is Crab_Data`，Prefab 仍可能回退到顶层 `Assets/GameObject`。

另外，如果直接覆盖导出到已有 `ExportedProject`，旧导出留下的顶层目录不会自动清理。验证目录结构是否真的改变时，应该先备份或清空旧的 `ExportedProject`，否则残留文件会让结果看起来没有变化。

## 修正要点

1. `SerializedAssetCollection` 必须保存来源文件路径。
2. `PreserveContainerPath` 模式下，路径解析顺序应为：
   - 优先使用 `asset.OriginalPath`
   - 没有可用 `OriginalPath` 时使用 `asset.Collection.FilePath`
   - 最后才回退到原有类型目录逻辑
3. 来源文件路径按 Unity 数据目录截断，例如：
   - `D:/Game/Everything is Crab_Data/sharedassets1.assets`
   - 导出到 `Assets/Everything is Crab_Data/sharedassets1.assets/类型名`
4. 对 Addressables 或 AssetBundle 内部集合，外层 bundle 路径后追加集合名，例如：
   - `Assets/Everything is Crab_Data/StreamingAssets/aa/StandaloneWindows64/example.bundle/CAB_xxx/类型名`
5. 处理阶段生成的 Prefab 应使用根 `GameObject` 的来源集合路径来决定目录，但仍使用 Prefab 自身的名字和导出格式，例如：
   - `Assets/Everything is Crab_Data/sharedassets7.assets/GameObject/AbilityMiniCard.prefab`

## 类比理解

之前的逻辑像是只看包裹上写着详细收货地址的物品。没有地址的物品仍然被仓库按品类放到货架上。

修正后，如果包裹没有详细地址，就先看它来自哪辆货车和哪个箱子，再放到对应的货车目录和箱子目录下面。这样至少能保留游戏文件来源结构，而不是全部散到顶层类型目录。

## 验证现象

修正并重新导入导出后：

- `Assets` 顶层出现 `Everything is Crab_Data`
- 普通资源进入类似 `Assets/Everything is Crab_Data/sharedassets1.assets/MonoBehaviour`
- Prefab 进入类似 `Assets/Everything is Crab_Data/sharedassets7.assets/GameObject/AbilityMiniCard.prefab`
- 顶层不再出现旧的 `AnimationClip`、`Texture2D`、`Shader`、`GameObject` 等主要类型目录
- `Scripts`、`Resources`、`Scenes`、`Plugins`、`Editor` 等目录仍可能存在，因为它们来自脚本导出、资源容器路径、场景、插件复制或 AssetRipper 生成文件
